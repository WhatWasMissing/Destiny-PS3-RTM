# Destiny RTM prerelease — 2026-10-28 revision 11

This build fixes numeric memory-address handling in the shared write runner.
JavaScript numeric addresses are now kept as numeric values instead of being
reinterpreted as hexadecimal strings. This was affecting the player-hook
installer, which passes numeric cave addresses. Patch ranges that would cross
the 32-bit address boundary are rejected before a write is sent.

The shared server-hook writer now preflights, recognizes, and clears the full
332-byte region required by the longest known payload. A fake-console
integration check installs Void, switches to Relative OPK, then switches Off;
it verifies the complete payload and zero padding and checks that the first
byte beyond the region remains unchanged. Local `D:\DestinyRTM` payloads match
the app constants byte-for-byte, and the BLES 01.24 EBOOT contains the expected
hook-site instruction and a 384-byte zero-filled static cave. See
[`research/server-hook-source-audit.md`](../research/server-hook-source-audit.md)
for hashes and limits of that evidence.

These checks do not establish live gameplay effects. The development PS3 at
`192.168.0.62` did not respond to the latest connectivity probe, so this build
was not validated on a live console. Enemy spawning remains experimental and
unconfirmed on hardware. Inventory mutation remains unimplemented because no
BLES 01.24 write target and request format are verified; see
[`research/inventory-action-evidence.md`](../research/inventory-action-evidence.md).
