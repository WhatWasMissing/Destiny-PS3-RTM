# Destiny RTM prerelease — 2026-10-28

This build adds a read-only BLES 01.24 allocated-actor candidate snapshot to
the CLI and MCP server. It follows the verified allocator bitmap, reconstructs
full actor datums, and returns selected words from the first `0x48` bytes of
each allocated record (maximum 40 slots). It does not classify enemies,
choose spawn tags, or write memory.

## Build verification

- Go: `go test ./...` passed.
- JavaScript: 104 tests passed.
- Packaged desktop, CLI, and MCP protocol smoke checks passed.
- No PS3 requests were sent during the build. Live pointer layout, actor-to-
  enemy correlation, and spawning remain unverified on the development console.

## Snapshot limits

Actor allocation does not prove that a slot is a live enemy or a spawnable
tag. Reads are sequential; the client cannot identify a process restart at
reused addresses or rule out ABA reuse. The experimental spawn executor still
needs a live BLES 01.24 development-console run before its worker, tag/class
mapping, or placement can be claimed as working.
