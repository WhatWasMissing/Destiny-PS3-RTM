Server Cheats Safety Guide

Important: Server Cheats are experimental and highly volatile. Switching modes too quickly or sending another action before the previous one finishes can make the game unstable or cause a crash.

Before using Server Cheats

  • Make sure the RTM is connected and Destiny is in a stable state.
  • Use only one Server Cheats mode at a time.
  • After selecting a mode, wait for the RTM confirmation before touching another Server Cheats control.
  • Do not repeatedly click the same mode while it is being applied.
  • If the game begins behaving unexpectedly, select Off and stop changing Server Cheats modes.

Relative OPK

When Relative OPK is active, the X, Y and Z controls adjust where affected enemies are positioned relative to your Guardian. Make small changes and allow each update to complete before adjusting them again.

Why this lock exists

Server Cheats apply a sequence of changes when a mode is selected. Rapidly sending more changes before the current sequence finishes can overwhelm the console with requests and cause instability.

Remember: Wait for confirmation before every mode change. This section remains locked until you acknowledge the guide.

Activity Loader Guide

The Activity Loader module allows you to force-load specific missions, strikes, raids, and destinations.

First-time setup: read this guide and scroll to the bottom. The Activity Loader will stay locked until you confirm you have read it.
Known Issue & Prerequisite

The "Read Current" command does not work as intended in the current build. Before sending a load command, you must manually select or start an activity in-game first. Attempting to overwrite the activity address without an active in-game target queued can lead to unexpected behavior or game crashes.

Usage Steps

  1. Establish Connection: Connect the web tool to your PS3 using your console's IP address.
  2. Set In-Game Target: In Destiny, select or initiate an activity using the Director menu so the game registers an active activity state.
  3. Locate Activity Loader: Expand the Activity Loader panel in the RTM tool interface.
  4. Choose Destination:
    • Use the Search activity… field to filter through the destination list.
    • Choose your desired activity from the dropdown menu.
  5. Execute Load: Click Load Activity to push the changes.

    What does “Instance Leader” mean?

    Instance Leader is the player whose console is currently handling authority for parts of the activity. Destiny 1 uses a hybrid network setup, so some activity hosting work can be handled by a player's console rather than everything being controlled from one central game server.

    This matters because some cheats that change enemy behaviour or enemy state can behave differently depending on whether your console is currently the Instance Leader. For example, an effect may apply properly to enemies when you are the Instance Leader, but behave differently or have limited effect when another player holds that role.

    It is not the same as Fireteam Leader. Being the person who formed the fireteam does not guarantee that you are the Instance Leader. Destiny chooses the hosting role separately, and it can move to another player while the instance is running.

    If a cheat mentions Instance Leader and appears to work differently between sessions, this is likely why. You normally do not need to change anything manually; just be aware that the result can depend on which console currently has that role.

    Conflict Detection: Infinite Power and Unlimited Abilities share a patch; 4× Jump Boost shares a patch address with Unlimited Abilities; Rock Jump and No Pushback Barriers share the same 12 bytes. Enabling a conflicting option disables the active one first.
    Status: Off = default/inactive · Applying = change in progress · On = last successful enable · Failed = last action failed. Feature labels describe the current confidence/stability of each option.

            Why this is experimental
            
    
              
    The operation-1 executor and queue layout were reconstructed from Blackrock's BLES 01.24 program. A matching live run has not confirmed instruction-cache behavior, tag resolution, runtime class, or spawn placement.
    
              
    The expected-type field defaults to -1, which disables that guard. Catalog type values look like object-kind ordinals, but their direct link to the BLES runtime class byte has not been proven. The shared queue has no cross-client reservation, so another Blackrock or RTM spawn client can collide with this one.

The tag must resolve in the running game; the optional tag lookup only checks a pointer candidate and does not prove it is an enemy.

Blackrock installs its base bootstrap during runtime setup and lazily ensures the spawn handler on dispatch; this RTM combines both setup stages in this one button. If Destiny restarted since an earlier install, recover its stale journal before installing again.
